# Changelog

All notable changes to sveltekit-ai-starter-template, newest first. SemVer, 0.x is pre-release. The heading
format is a contract, keep it: `## v<Version> · <YYYY-MM-DD> · <Title>`. Lines under
`## Unreleased` move under the next version heading at release; the version in `package.json`
is the topmost released one here.

## Unreleased

- Auth and sessions run through `@loewen-digital/fullstack` (`auth`, the `security` rate limiter, `mail` with its Resend driver) with the SvelteKit adapter; Lucia and its Drizzle adapter are gone. The session cookie is now `fs_token` and carries an opaque token; sessions last seven days from login and no longer extend on use. A password reset or change revokes every session of the user, and a new verification or reset link replaces the older ones. Reset and verification tokens are stored as issued, no longer hashed (loewen-digital/fullstack#27). Existing sessions do not carry over. See [decision 0006](docs/decisions/0006-fullstack-auth-on-flatdb.md).
- Data lives in `@loewen-digital/flatdb`: JSON documents validated by the zod schemas in `src/lib/server/collections/`, one database per request on `locals.db`. `npm run dev` writes to `.data/` (ignored by git) through an adapter with atomic writes and compare-and-swap, because flatdb's own `FsAdapter` tears `_index.json` when requests write in parallel (loewen-digital/flatdb#10); unit tests use `MemoryAdapter`, production the R2 bucket bound as `CONTENT` in `wrangler.jsonc`, and the README says how to create it. Drizzle, SQLite, D1, the `drizzle/` folder, the `db:*` scripts and `better-sqlite3` are gone, and with them the migrations and the better-sqlite3 crash on Node 24. Data in D1 or `local.db` does not carry over; re-register local users.
- Gaps found in the libraries are filed upstream and worked around where possible, marked `UPSTREAM`: `resetPassword` hides the user id (loewen-digital/fullstack#25), older one-time tokens stay valid (loewen-digital/fullstack#26), tokens are stored raw (loewen-digital/fullstack#27), no unique field constraint (loewen-digital/flatdb#9), `FsAdapter` not safe under concurrent writes (loewen-digital/flatdb#10), collection types lose the schema (loewen-digital/flatdb#7).
- Tailwind colour utilities carry the element-library token names: `bg-accent`, `text-fg`, `text-fg-muted`, `bg-bg`, `bg-bg-muted`, `border-border`, `text-danger`, … (`bg-primary`, `text-text-primary`, `bg-surface` and the unused hover/surface tokens are gone). The toast store and `ToastContainer` are removed; create an `el-notification` and call `toast()` instead. See [decision 0005](docs/decisions/0005-tailwind-names-are-token-names.md).
- Node 24 is the required version (`engines.node` in `package.json`); CI, deploy and the agent workflow read it from there.
- The design system is `@webtides/element-library`, used directly: pages write `<el-button>`, `<el-input-field>`, `<el-password-field>`, `<el-notification>` and `<el-dialog>` instead of the former `Button`, `Input`, `Alert`, `Toast` and `Modal` Svelte components, which are gone. `src/hooks.server.ts` pre-renders every `el-*` element as Declarative Shadow DOM through `@webtides/element-js-ssr-renderer`, the root layout upgrades them on the client, and everything works on Cloudflare Workers. Forms post natively; client validation reads `formData`. `SubmitButton` is the one remaining wrapper: it adds the light-DOM submit button that `el-button` lacks (Enter, pre-hydration clicks, no JavaScript; webtides/element-library#86). See [decision 0004](docs/decisions/0004-elements-directly-no-wrappers.md), which supersedes [0002](docs/decisions/0002-button-wrapper-with-light-dom-submit.md).
- Theme: `@webtides/element-library/themes/default.css` plus the project override `src/lib/design/theme.css`; Tailwind's semantic colours (`bg-primary`, `text-danger`, …) alias the `--el-*` tokens, and dark mode follows `color-scheme` via `light-dark()`.
- Upstream gaps are worked around in one place each and marked `UPSTREAM`: server-rendered notifications stay visible before their JavaScript runs (webtides/element-library#87), fields without a `value` attribute no longer render `value="null"` (webtides/element-js#167), and missing type declarations are shimmed in `src/lib/design/vendor.d.ts` (webtides/element-library#85, webtides/element-js-ssr-renderer#13), and the attribute typings in `src/lib/design/elements.d.ts` stay hand-written until the library ships them (webtides/element-library#89). A client-rendered notification shows no icon until webtides/element-library#88 is fixed.
- The profile forms show the server's success message inline instead of a toast, so a password or email change is confirmed even when the form posts natively; see [decision 0003](docs/decisions/0003-profile-feedback-inline-not-toast.md).
- `src/lib/design/DESIGN-SYSTEM.md` describes the element-library based system; the design rules in `AGENTS.md` point at it. Playwright checks accessibility with axe on the login and register pages, the login form without JavaScript (server-rendered, submit, error message) and Enter to submit after hydration. The auth pages gained a `<main>` landmark, a `<title>` and underlined inline links, which axe required.
- Passwords are hashed with scrypt from `node:crypto` instead of `@node-rs/argon2`, so the app runs on Cloudflare Workers (`wrangler dev` and deploys were broken). Existing argon2 hashes no longer verify, re-register local users. The `prebuild` step and the wasm package are gone. See [decision 0001](docs/decisions/0001-scrypt-instead-of-argon2.md).
- Agent rules live in `AGENTS.md`; `CLAUDE.md` only imports it. The Codex review rules are a section of the same file.
